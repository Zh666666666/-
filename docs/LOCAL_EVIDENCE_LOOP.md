# 单传感器无服务器闭环

## 目标

在不依赖生产服务器、数据库和第二只传感器的条件下，使用一只真实
`WT9011DCL-BT50` 完成可保存、可结束、可导出、可回放、可处置和可追溯的工程闭环。

```text
真实 BLE 连接
  -> 创建本地任务
  -> 加密保存 Acc/Gyro/Angle
  -> 记录断连/断帧/静止/强运动事件
  -> 用户结束任务
  -> Android 导出标准 JSON
  -> Web 导入回放
  -> 逐条确认并处理事件
  -> 导出闭环处理报告
```

本闭环只证明产品能够处理真实硬件任务，不声明临床 ROM、跌倒诊断或医疗效果。

## Android 本地任务

- 点击“开始本地采集”不要求平台地址或服务器可用。
- 必须先连接至少一只真实 BT50，避免创建无硬件来源的空任务。
- 原始 SDK 读数最多按 2Hz 写入证据任务；10Hz 实时可视化保持不变。
- 每个样本独立使用 AndroidX `EncryptedFile`（AES-256-GCM）写入应用私有目录。
- 每个任务最多 20,000 个样本；达到上限时自动结束并生成需处理事件。
- App 在任务进行中异常退出时，下次启动会将任务标记为中断并封存已有数据。
- 平台配置有效时仍可同步上传，但上传只是可选旁路，不影响本地任务成立。

## 工程事件

| 事件 | 规则 | 是否要求处理 |
| --- | --- | --- |
| 设备断开 | 采集中收到 BLE disconnect | 是 |
| 长断帧 | 同一位置相邻保存样本超过 3 秒 | 是 |
| 长时间静止 | 连续 60 秒加速度接近 1g 且角速度低于 3°/s | 是 |
| 强冲击/剧烈运动 | 加速度合量不低于 2.5g，或角速度合量不低于 300°/s | 是 |
| 任务中断 | 上次 ACTIVE 任务未正常结束 | 是 |
| 任务开始/结束/重连 | 生命周期审计事件 | 否 |

这些阈值用于工程异常检测。强运动事件不等于跌倒，静止事件也不等于患者没有活动。

## 证据包契约

Android 导出 `tka-local-evidence/v1` JSON：

- `session`：任务 ID、对象 ID、HARDWARE 来源、BT50 型号、App 版本、开始/结束时间和结束原因；
- `samples`：设备、位置、时间及 Acc/Gyro/Angle 三轴值；
- `events`：事件类型、严重度、证据、时间及是否要求处理；
- 清单中的样本数和事件数必须与数组实际数量一致，否则 Web 拒绝导入。

导出前，手机内文件保持加密。导出是用户主动操作，生成的 JSON 为可读文件，应由用户保存到受控位置。

## Web 回放与处置

访问 `/evidence`，打开或粘贴 Android JSON。Web 会：

1. 校验版本、HARDWARE 来源、BT50 型号、字段和数量一致性；
2. 计算任务时长、实际采样率、姿态范围、最大加速度和最大角速度；
3. 回放 Roll/Pitch/Yaw 曲线；
4. 展示全部事件，要求需处理事件填写说明后才能关闭；
5. 将处理状态保存在当前浏览器 `localStorage`；
6. 导出 `tka-local-evidence-review/v1` 处理报告。

任务状态为 `COMPLETED`，且所有 `requiresAction=true` 事件均为 `RESOLVED` 时，页面显示“本次任务闭环完成”。

## 验收步骤

1. Android 扫描并连接真实 BT50。
2. 不填写平台地址，点击“开始本地采集”。
3. 静止、转动传感器，并在采集中关闭一次传感器制造断连事件。
4. 重新连接后结束任务。
5. 点击“导出最近证据包”并保存 JSON。
6. 在 Web `/evidence` 导入 JSON，确认来源显示 `HARDWARE`。
7. 检查曲线、样本数量、实际采样率和事件时间线。
8. 为断连等需处理事件填写说明并标记已处理。
9. 页面显示闭环完成，导出处理报告。
10. 重启 Android 和刷新 Web，确认最近任务仍可导出、浏览器处理状态仍保留。

完成上述十步即可证明单传感器、无服务器工程闭环成立。
