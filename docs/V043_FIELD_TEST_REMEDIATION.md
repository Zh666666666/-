# v0.4.3 实物测试缺陷与改造验收

最后更新：2026-07-26

本文记录 v0.4.3 正式签名 APK 在两只 WT9011DCL-BT50 实物上的测试结果，
作为后续 Agent 的实现与验收依据。除“已确认”项外，不得把计划描述成已完成。

## 已确认事实

- Android 端实时数值更新及时，两只传感器可连接、分配并采集真实数据。
- Web 更新速度较 v0.4.2 改善，但仍明显落后于手机。实测页面显示
  “手机采集到服务器”约 272 秒、“采集到当前网页”约 279 秒。
- Android 单轮可批量上传 80 条，但队列仍可积压约 230 条；实时采集速度高于
  持续上传清空速度。
- 结束训练与证据包导出不再必然闪退，证据任务可在 Web 回放。
- 一次 774 秒任务仅形成 867 条服务器样本，实际采样率约 1.12 Hz，并产生
  95 项“待处理事件”；正常屈膝也可能被强晃动/高风险规则误报。
- 指标质量门可得到 `Q=83` 并输出 ROM、峰值、次数和活动时间，但风险区仍把
  “数据中断”“趋势回退”“强晃动”作为显著预警，普通用户难以判断是否真的危险。
- 家属“易懂视图”仍包含 ROM、屈曲度、质量门、回执、传感器等专业概念，
  页面第一视觉重点不明确。
- 护膝/设备电量显示长期不变，尚无证据证明来自 BT50 的真实电量值。
- 设备绑定、患者资料或测试上下文没有形成用户可感知的持久闭环；重新测试时
  用户仍需重复绑定。
- Web 缺少清晰的历史训练与异常事件回顾入口。
- 资料页缺少退出/返回登录、修改密码；登录页缺少忘记密码、密码重置，
  已上线的邮箱验证码注册入口当前不可见。

## 产品边界

- 家属默认只需要回答三个问题：现在是否正常、需要做什么、最近是否变好。
- ROM、原始角度、质量门、同步误差、回执、算法公式和原始帧保留在专业详情，
  不作为家属首屏的主要信息。
- 任何没有从传感器或官方 SDK 读到的电量必须显示“暂不可读取”，不得使用固定值、
  随机值或推算值冒充真实电量。
- 风险规则必须先通过数据新鲜度、双路同步、校准与动作质量检查。质量不足只能
  输出“本次数据不足/请重新测量”，不能升级成患者高风险。
- AI 只能解释确定性引擎已经形成的结构化证据，不得自行把单次晃动解释成诊断。

## 改造顺序

### P0：实时链路与数据积压

1. 分别测量 BLE 入帧率、落盘率、入队率、批量请求吞吐、服务器接收率和 Web 最新帧率。
2. 上传调度必须“实时优先、历史补传限速”：当前会话最新帧不得排在数百条旧帧之后。
3. 在线稳定网络下连续 30 分钟，队列应收敛而不是持续增长。
4. Web 默认读取每个位置最新的已确认样本；历史补传不得把实时视图时间倒退。
5. App 显示采集、已确认上传、待补传、隔离四类计数，避免“本轮上传”造成误解。

验收：

- 在线 10 分钟后队列不持续增长，60 秒内回到可控水位。
- App 到 Web 最新帧延迟 P95 不超过 2 秒，且不会随运行时长线性扩大。
- 断网恢复后补传不会阻塞当前实时帧；结束会话后不再产生新实时数据。

### P0：指标质量门与误报

1. 将“数据质量问题”和“患者风险”彻底分层。
2. 检查 BT50 官方量程、单位换算、时间戳、异常尖峰和重复帧；对超物理范围样本先标记
   为传感器/链路异常，不直接触发患者跌倒或高风险。
3. 正常缓慢屈伸建立独立基线测试，覆盖 ROM、峰值、完整次数、有效时间和风险分。
4. “趋势回退”必须满足可比会话、足够样本、相同佩戴/校准条件和最小变化幅度。
5. 待处理事件需要去重、合并相邻事件并提供普通语言原因。

验收：

- 标准缓慢屈伸不会产生强冲击或高风险误报。
- 数据中断只显示设备/网络提示，不计入患者风险分。
- 每个风险结论都能追溯到规则、输入区间、持续时间和处置建议。

### P0：真实电量与设备持久化

1. 先核对项目内 BT50 官方资料、WitSDK 可用字段和 BLE GATT 服务是否提供电量。
2. 能读取时保存原始电量值、读取时间和来源；不能读取时明确显示未知。
3. 设备地址、用户命名、大腿/小腿分配、患者绑定和最近校准版本持久化到服务端。
4. App 重连后恢复既有绑定；只有换设备、换位置或用户主动解除时要求重新确认。

验收：

- 电量值有明确真实来源并随设备状态变化，或显示“设备暂不支持读取”。
- 退出再登录、重新测试和 App 重启后绑定仍存在，且不会串到其他患者。

### P1：历史训练与异常回顾

1. 新增按患者隔离的训练历史列表：日期、时长、完成状态、数据质量、家属结论。
2. 训练详情展示普通摘要、趋势、异常时间线和可展开专业证据。
3. 支持筛选未处理事件、查看处理记录，并从当前实时页进入本次会话详情。

验收：

- 完成训练后可在历史中立即找到，刷新和重新登录后仍存在。
- 家属只能看所属患者；护士按授权患者查看并处理异常。

### P1：账号与资料闭环

1. 资料页增加退出登录/返回登录页、修改密码和会话信息。
2. 登录页恢复邮箱注册入口；保持护士账号不公开注册。
3. 增加忘记密码：邮箱验证码、短期重置凭证、密码强度和频率限制。
4. 资料页补充姓名/称呼、角色、联系方式、关联患者、通知偏好、设备与账号安全摘要。

验收：

- 注册、登录、退出、修改密码、忘记密码重置、旧密码失效均通过真实邮箱测试。
- 不同角色退出后可以明确切换账号，受保护页面不能通过浏览器返回继续访问。

### P1：家属信息架构

1. 首屏唯一主结论使用普通语言：正常、需要留意、数据不足。
2. 第二层只给下一步动作和最近训练变化。
3. 第三层才展示训练次数、完成度和设备状态。
4. ROM、角度、质量门、原始数据、3D、算法链路统一放入“专业详情”。
5. 护士端保留专业指标，但将数据质量、患者风险和人工处理状态分区展示。

验收：

- 不了解康复和传感器的用户能在 5 秒内回答“有没有问题”和“现在该做什么”。
- 家属首屏不出现未解释的英文原因码、回执、P95/P05、同步帧或质量门术语。

## 实施进度

### 2026-07-26 P0 第一检查点

- Android 加密队列改为实时/补传平衡批次：每批优先包含最新实时帧，同时保留
  四分之一吞吐清理最旧历史帧；成功、永久拒绝与可重试样本按文件键独立确认，
  不再要求严格 FIFO 前缀成功。
- 批量 API 单批并发由 6 提升至 20，减少 100 帧批次在服务器内部串行等待。
- 强运动事件改为 1.2 秒三样本序列判定，必须同时出现低加速度、冲击峰值和
  高角速度；单独高角速度的正常快速屈伸不再触发。
- 数据断帧、长时间静止、设备断开、App 中断与存储上限属于技术/运行日志，
  不再默认进入“需要处理”。
- 尚待真机确认在线队列是否收敛、最新帧 P95 是否达到 2 秒；未完成前不得标记 P0
  实时链路验收通过。

### 2026-07-26 P0/P1 软件改造检查点

- 正常训练误报进一步收紧：疑似冲击必须在同一设备 1.2 秒窗口内依次出现
  “低重力→大于等于 3g 冲击→大于等于 500°/s 角速度”，反向或仅高速屈伸不触发，
  Android 端同类事件 10 秒内去重。数据断帧、静止和设备断开仍仅属于运行提示。
- 结束训练使用完整会话原始帧计算摘要和 AI 证据，不再只读取前 2,000/20,000 帧；
  训练摘要、异常证据和智能解读保留 15 天，逐帧数据保留 72 小时。
- 每次已结束训练均保存三态家属结论：正常、需要关注、数据不足；质量较低时保留结果并
  降低置信度，不把校准、网络或传感器问题计为患者风险。AI 解读按高/中/低置信度标注，
  完成训练后由服务端自动触发。
- 家属和护士均新增近 15 天训练历史，默认显示普通语言结论与下一步，专业详情才展示
  ROM、次数、质量、异常证据和 AI 原文。家属历史接口强制限定到所属默认患者。
- 登录页恢复家属邮箱注册入口并新增忘记密码；新增邮箱验证码重置、登录后修改密码、
  退出登录。资料页支持姓名、联系方式、患者关系和通知偏好，护士可维护科室/职称，
  医疗资料不开放给家属修改。
- Android 仅从 WitMotion SDK 官方 `Electricity` 寄存器轮询结果读取电量并上传来源；
  SDK 未返回时 App 与 Web 显示未知，不再使用固定的 92% 等占位值。
- Android 采集与上传仍保留每个 SDK 原始帧，3D、波形和文字刷新单独限制为每只传感器
  最多 10Hz，避免渲染抢占采集与按钮响应。

本检查点软件验证：

- `npm test`：44 项通过（29 runtime + 9 gateway + 6 API）。
- `npm run lint`、`npm run build`：通过，48 个 Web 路由完成生产构建。
- Android `verify-debug.ps1`：JVM、Lint、Debug APK 构建通过。
- 仍需安装新 APK 做两只实物传感器的 30 分钟队列收敛、P95 小于 2 秒、真实电量变化和
  正常屈伸零误报验收；这些真机指标在复测前不得标记为通过。
